# راهنمای فارسی نصب و راه‌اندازی Traider

> تصحیح وضعیت: هدف پروژه LBank است و پیش‌فرض به LBank برگشته است. اتصال کندل و معامله فیوچرز آن هنوز کامل نشده؛ راهنمای جاری و ابزار بررسی بدون کلید در [README_LBANK_FA.md](README_LBANK_FA.md) است. مثال‌های OKX در این فایل مسیر آزمایش‌شده قبلی را توضیح می‌دهند و برآورده‌شدن درخواست LBank محسوب نمی‌شوند.

این پروژه یک ربات پایتونی برای تحلیل قرارداد دائمی خطی با تسویه USDT است. تحلیل تکنیکال محلی، پیشنهاد Gemini، محاسبه حجم و ریسک، مدیریت حد ضرر و سود، ذخیره وضعیت در SQLite و کنترل از تلگرام در آن پیاده‌سازی شده است.

پیش‌فرض فعلی `OKX` و حالت **شبیه‌سازی** است. در شبیه‌سازی قیمت واقعی دریافت می‌شود، اما سفارش واقعی ارسال نمی‌شود و موجودی مجازی است. برای این حالت کلید صرافی لازم نیست؛ کلید Gemini و توکن تلگرام لازم است. این برنامه بک‌تستر نیست و سودآوری استراتژی اثبات نشده است. اهداف سود روزانه فقط شرط توقف برنامه‌اند، نه وعده سود.

## ۱. پیش‌نیازها

- Python 3.12 نسخه ۶۴ بیتی؛ در ویندوز هنگام نصب، گزینه افزودن Python به PATH را فعال کنید.
- دسترسی شبکه به صرافی انتخابی، Telegram و Gemini API.
- یک ربات تلگرام و یک کلید Gemini.
- برای روش Docker، نصب Docker و افزونه Compose به‌جای نصب مستقیم Python کافی است.

راهنما برای مسیر فعلی `D:\MyProjects\Traider` نوشته شده است. اگر پوشه را جابه‌جا کردید، مسیر دستورها را عوض کنید. محیط `.venv` قابل جابه‌جایی بین سیستم‌ها نیست؛ آن را در سیستم جدید دوباره بسازید.

## ۲. ساخت ربات تلگرام و گرفتن شناسه خودتان

۱. در تلگرام حساب رسمی [BotFather](https://t.me/BotFather) را باز کنید.
۲. دستور `/newbot` را بفرستید، نام و نام کاربری ربات را تعیین کنید و توکن دریافتی را نگه دارید.
۳. رباتی را که ساخته‌اید باز کنید و `/start` بفرستید.
۴. برای گرفتن chat ID بدون سرویس شخص ثالث، پیش از اجرای ربات در PowerShell از دستورهای زیر استفاده کنید. توکن در ورودی مخفی دریافت می‌شود:

```powershell
$botToken = Read-Host 'Telegram bot token' -MaskInput
$updates = Invoke-RestMethod -Uri ('https://api.telegram.org/bot' + $botToken + '/getUpdates')
$updates.result | ForEach-Object { $_.message.chat | Select-Object id, type }
Remove-Variable botToken, updates
```

از مقدار `id` گفت‌وگوی خصوصی خودتان استفاده کنید؛ باید یک عدد مثبت باشد. اگر خروجی خالی است، دوباره به ربات پیام بدهید. این دستور را زمانی اجرا کنید که خود برنامه در حال polling نیست. قابلیت `-MaskInput` به PowerShell 7 نیاز دارد؛ در Windows PowerShell 5 از PowerShell 7 استفاده کنید.

کنترل ربات به همین گفت‌وگوی خصوصی محدود می‌شود. شناسه گروه یا کانال وارد نکنید. توکن، کلیدها و فایل `.env` را عمومی منتشر نکنید.

## ۳. ساخت کلید Gemini

از [Google AI Studio](https://aistudio.google.com/api-keys) کلید API بسازید و آن را در `GEMINI_API_KEY` قرار دهید. کلید به پروژه Google شما وابسته است؛ سهمیه و دسترسی مدل را در همان حساب بررسی کنید. [راهنمای رسمی کلیدهای Gemini](https://ai.google.dev/gemini-api/docs/api-key)

نام مدل از `GEMINI_MODEL` خوانده می‌شود و مقدار اولیه `gemini-2.5-flash` است. موجود بودن این مدل برای حساب شما با ابزار بررسی اتصال کنترل می‌شود؛ اگر دسترسی ندارید، نام مدل قابل دسترس در حساب خود را جایگزین کنید. پروژه رایگان بودن API یا دسترسی از همه مناطق را تضمین نمی‌کند.

## ۴. نصب مستقیم در ویندوز

PowerShell را باز کنید:

```powershell
Set-Location D:\MyProjects\Traider
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

اگر فایل `.env` دارید، آن را با فایل نمونه جایگزین نکنید. اگر `py` شناخته نمی‌شود ولی Python نصب است، دستور `python -m venv .venv` را استفاده کنید. اگر `python` فروشگاه ویندوز را باز می‌کند، نصب Python و تنظیم PATH یا App execution aliases را اصلاح کنید.

در فایل `.env` حداقل این موارد را تکمیل کنید:

```dotenv
TELEGRAM_BOT_TOKEN=توکن_واقعی_ربات
TELEGRAM_ADMIN_CHAT_ID=123456789
GEMINI_API_KEY=کلید_واقعی_شما
GEMINI_MODEL=gemini-2.5-flash
EXCHANGE_ID=okx
SYMBOL=BTC/USDT:USDT
DRY_RUN=true
USE_TESTNET=false
STARTING_BALANCE=10
```

عبارت‌های فارسی بالا نمونه‌اند و باید با مقدار واقعی جایگزین شوند. برای شبیه‌سازی، متغیرهای `EXCHANGE_API_KEY`، `EXCHANGE_API_SECRET` و `EXCHANGE_API_PASSWORD` را خالی بگذارید. `USE_TESTNET=false` در حالت DRY فقط یعنی داده عمومی از محیط اصلی دریافت می‌شود؛ سفارشی ارسال نمی‌شود.

اجرای دستورها به فعال کردن محیط مجازی نیاز ندارد، چون مسیر Python آن را مستقیماً استفاده می‌کنیم. بنابراین تغییر ExecutionPolicy ویندوز هم لازم نیست.

## ۵. بررسی نصب و نخستین اجرا

```powershell
.\.venv\Scripts\python.exe check_setup.py
.\.venv\Scripts\python.exe check_setup.py --network
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py
```

دستور اول تنظیمات را بررسی می‌کند. گزینه `--network` بازار و کندل‌ها، هویت ربات و دسترسی به مدل Gemini را بررسی می‌کند؛ سفارش و درخواست تولید متن ارسال نمی‌کند. این بررسی، درست بودن chat ID مدیر یا مجوز معامله صرافی را تأیید نمی‌کند؛ دریافت پیام شروع و تست حساب Demo آن‌ها را روشن می‌کند.

بعد از اجرا باید پیام شروع در تلگرام دریافت کنید. `/status` را بفرستید؛ حالت باید شبیه‌ساز باشد. بسته نشدن ترمینال طبیعی است؛ برنامه پیوسته کار می‌کند. برای خروج `Ctrl+C` بزنید.

اگر سیگنالی دریافت نمی‌کنید، لزوماً برنامه متوقف نشده است: ابتدا باید شرایط تکنیکال برقرار شوند، سپس Gemini پیشنهاد قابل قبول بدهد و مدیریت ریسک حجم را تأیید کند. برنامه برای ایجاد معامله اجباری طراحی نشده است.

## ۶. نصب در Linux

با فرض نصب Python 3.12 و ماژول venv در سیستم، از پوشه پروژه اجرا کنید:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
nano .env
.venv/bin/python check_setup.py --network
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python main.py
```

فایل `requirements-lock.txt` خروجی محیط آزمایش‌شده Windows/Python 3.12 است و شامل بسته‌های مخصوص ویندوز می‌شود. برای نصب قابل حمل و Docker از `requirements.txt` استفاده کنید. قفل نسخه Linux در این بررسی تولید نشده است.

## ۷. اجرای Docker

در پوشه پروژه، فایل `.env` را مطابق مراحل قبل آماده کنید، سپس:

```bash
docker compose build
docker compose run --rm trader python check_setup.py --network
docker compose up -d
docker compose logs -f --tail=100
docker compose ps
```

برای توقف و به‌روزرسانی:

```bash
docker compose down
docker compose up -d --build
```

وضعیت و تاریخچه در volume به نام `trader-data` ذخیره می‌شود. دستور `docker compose down -v` داده‌ها را حذف می‌کند؛ برای توقف معمولی از آن استفاده نکنید. Healthcheck فقط زنده بودن حلقه برنامه را با heartbeat بررسی می‌کند؛ سالم بودن اتصال صرافی یا سودآوری را نشان نمی‌دهد. Docker صرفاً با unhealthy شدن کانتینر آن را خودکار restart نمی‌کند؛ سیاست restart برای خروج فرایند است.

Docker در محیط این بررسی نصب نبود؛ فایل‌ها تهیه شده‌اند اما ساخت و اجرای کانتینر در این محیط آزمایش نشده است.

## ۸. فرمان‌های تلگرام

| دستور | کاربرد |
| --- | --- |
| `/start` یا `/help` | نمایش راهنما و دکمه‌ها |
| `/status` | موجودی، وضعیت، پوزیشن و مصرف AI |
| `/pause` | توقف ورود جدید؛ مدیریت پوزیشن باز ادامه دارد |
| `/resume` | ادامه اسکن با رعایت محدودیت ریسک |
| `/mode` | انتخاب شبیه‌سازی یا اجرای واقعی؛ ورود به LIVE تأیید تلگرامی می‌خواهد |
| `/panic` | تأیید و سپس لغو سفارش‌ها و تلاش برای بستن پوزیشن نماد تنظیم‌شده |
| `/history` | معاملات اخیر و خلاصه عملکرد |
| `/resetdry 10` | بازنشانی موجودی مجازی و آمار روزانه، فقط در DRY و بدون پوزیشن باز |

`/panic` فقط نماد `SYMBOL` را پوشش می‌دهد، نه تمام نمادهای حساب. هنگام خطا یا تأیید نشدن خروج باید وضعیت صرافی را بررسی کنید. `/pause` یا خاموش کردن برنامه پوزیشن را نمی‌بندد. توقف روزانه با `/resume` دور زده نمی‌شود.

## ۹. تنظیمات مهم

تمام متغیرها در `.env.example` آمده‌اند. مقادیر نسبتی اعشاری‌اند: `0.04` یعنی ۴ درصد، نه ۰٫۰۴ درصد.

| متغیر | پیش‌فرض | معنی |
| --- | --- | --- |
| `RISK_PER_TRADE_PCT` | `0.04` | بودجه زیان محاسباتی هر معامله نسبت به موجودی؛ شامل تخمین کارمزد و لغزش |
| `MIN_LEVERAGE` / `MAX_LEVERAGE` | `10` / `35` | بازه اهرم محاسباتی؛ محدودیت واقعی بازار هم باید اجازه دهد |
| `DAILY_PROFIT_TARGET_PCT` | `0.10` | توقف پس از سود روزانه محقق‌شده ۱۰٪ |
| `DAILY_MAX_LOSS_PCT` | `0.08` | توقف پس از زیان روزانه محقق‌شده ۸٪ |
| `MAX_CONSECUTIVE_LOSSES` | `2` | تعداد زیان متوالی برای توقف |
| `CIRCUIT_BREAKER_HOURS` | `24` | مدت توقف ناشی از زیان |
| `TP1_CLOSE_FRACTION` | `0.5` | سهم بستن در هدف اول، در صورت امکان تقسیم حجم |
| `CLOSE_AT_TP2` | `false` | در حالت false بعد از هدف دوم حد ضرر متحرک تنگ‌تر می‌شود |
| `AI_MAX_CALLS_PER_DAY` | `45` | سقف تلاش‌های API در روز، شامل retry |
| `AI_MIN_INTERVAL_SEC` | `900` | فاصله دو تحلیل مستقل؛ retryهای همان تحلیل زودتر انجام می‌شوند |
| `SCAN_INTERVAL_SEC` | `20` | فاصله اسکن برای ورود |
| `MONITOR_INTERVAL_SEC` | `3` | فاصله بررسی پوزیشن |
| `DATA_DIR` | پوشه `data` کنار کد | محل پایگاه داده، قفل اجرا، لاگ و heartbeat |

اگر درصد هدف سود یا زیان بزرگ‌تر از صفر باشد، مقدار دلاری همان محدودیت نادیده گرفته می‌شود. برای استفاده از مقدار دلاری، درصد مربوط را صفر بگذارید. روز معاملاتی و سهمیه AI براساس UTC بازنشانی می‌شوند؛ نمایش ساعت تلگرام براساس `Asia/Tehran` است.

این اعداد تنظیمات به‌جامانده پروژه‌اند؛ برنامه آن‌ها را به‌عنوان پیشنهاد سرمایه‌گذاری تأیید نمی‌کند. لغزش، گپ قیمت، Funding و تفاوت اجرای واقعی می‌تواند نتیجه را از تخمین تغییر دهد. Funding در مدل سود و زیان فعلی محاسبه نمی‌شود.

## ۱۰. پراکسی

در صورت داشتن پراکسی مجاز و فعال:

```dotenv
TELEGRAM_PROXY_URL=http://127.0.0.1:7890
EXCHANGE_PROXY_URL=http://127.0.0.1:7890
```

پورت را با مقدار واقعی جایگزین کنید. پراکسی تلگرام و صرافی جداگانه تنظیم می‌شوند. Gemini از تنظیمات استاندارد HTTP proxy محیط HTTPX، مانند `HTTPS_PROXY`، استفاده می‌کند. تنظیم عمومی پراکسی ممکن است روی سایر اتصال‌ها هم اثر بگذارد.

داخل Docker آدرس `127.0.0.1` خود کانتینر است؛ برای پراکسی روی میزبان Docker Desktop معمولاً باید از `host.docker.internal` استفاده کنید. پراکسی باید از داخل کانتینر قابل دسترس باشد.

## ۱۱. حساب Demo و اجرای LIVE

کد مسیر اجرای سفارش را دارد، اما در این بررسی معامله واقعی یا Demo انجام نشده است؛ کلید حساب و تلگرام کاربر در پروژه موجود نبود. تست‌های LIVE با صرافی ساختگی اجرا شده‌اند. مسیر اجرای واقعی باید ابتدا با حساب Demo خودتان تأیید شود.

برای OKX، کلید API، Secret و Passphrase لازم است؛ حساب باید از معاملات قرارداد دائمی پشتیبانی کند و Position Mode آن **Net / One-way** باشد. Hedge mode در این پروژه پشتیبانی نمی‌شود. برای Demo باید کلید مخصوص Demo بسازید. [مستندات رسمی OKX](https://app.okx.com/docs-v5/en/)

```dotenv
EXCHANGE_ID=okx
SYMBOL=BTC/USDT:USDT
DRY_RUN=false
USE_TESTNET=true
EXCHANGE_API_KEY=کلید_حساب_Demo
EXCHANGE_API_SECRET=سکرت_حساب_Demo
EXCHANGE_API_PASSWORD=پسفریز_همان_کلید
```

پس از تغییر `.env` برنامه را مجدداً اجرا کنید، `check_setup.py --network` را بررسی کنید و در تلگرام `/mode` را بزنید. در رابط برنامه، LIVE یعنی ارسال سفارش به صرافی؛ اگر `USE_TESTNET=true` باشد مقصد حساب Demo است. پشتیبانی‌نشدن sandbox باعث خطای توقف می‌شود و برنامه خودکار به محیط اصلی نمی‌رود.

حالت انتخاب‌شده در SQLite ذخیره می‌شود. در اولین نصب `DRY_RUN=false` پیش‌فرض را LIVE می‌کند؛ اگر قبلاً در همان DATA_DIR حالت DRY ذخیره شده باشد، با `/mode` تغییرش دهید. `DRY_RUN=true` همیشه ارسال سفارش واقعی را مسدود می‌کند. اگر پوزیشن LIVE ذخیره‌شده دارید، تغییر به DRY تا تعیین تکلیف آن با خطا متوقف می‌شود.

برای اتصال به حساب اصلی، کلید مربوط به همان حساب و `USE_TESTNET=false` لازم است. پیش از این تغییر، نتیجه Demo، مجوز معامله، حداقل حجم، مارجین Isolated و ثبت حد ضرر بومی را تأیید کنید. حد ضرر نرم‌افزاری فقط هنگام روشن بودن و اتصال برنامه کار می‌کند. خاموشی، کارمزد و لغزش می‌توانند سقف ریسک تخمینی را نقض کنند.

LBank از مسیر فعلی برای اجرای فیوچرز پشتیبانی نمی‌شود و LIVE آن عمداً رد می‌شود. نسخه بررسی‌شده CCXT در دریافت کندل قرارداد LBank هم خطای بازار داد؛ پیش‌فرض به OKX تغییر کرده است. استفاده آزمایشی از `EXCHANGE_ID=lbank` تنها با `MARKET_DATA_EXCHANGE_ID=okx` ممکن است، ولی منبع تحلیل و مشخصات بازار متفاوت خواهند بود. [محدودیت اتصال LBank در CCXT](https://docs.ccxt.com/docs/comparisons/ccxt-vs-lbank-api)

## ۱۲. ذخیره‌سازی، پشتیبان‌گیری و بازیابی

- `data/state.db`: پوزیشن، موجودی مجازی، حالت، توقف‌ها، مصرف AI و تاریخچه.
- `data/bot.log`: لاگ چرخشی، با حداکثر سه فایل پشتیبان.
- `data/heartbeat`: زمان آخرین heartbeat.
- `data/bot.lock`: جلوگیری از اجرای هم‌زمان دو نمونه روی یک DATA_DIR؛ باقی ماندن خود فایل نشانه قفل فعال نیست.

برای پشتیبان‌گیری، برنامه را متوقف و کل پوشه `data` را کپی کنید. با برنامه فعال، صرفاً کپی `state.db` ممکن است تغییرات WAL را جا بیندازد. هیچ‌وقت دیتابیس پوزیشن فعال را برای رفع خطا حذف نکنید. برای دو اجرای مستقل DATA_DIR جدا بدهید و هر حساب/نماد را فقط یک ربات مدیریت کند؛ قفل فایل جلوی دو پوشه مستقل با یک حساب صرافی را نمی‌گیرد.

اگر ارسال سفارش با قطع ارتباط روبه‌رو شود، وضعیت `UNKNOWN` ذخیره و اسکن متوقف می‌شود. برنامه برای جلوگیری از سفارش تکراری دوباره ورود نمی‌زند. وضعیت حساب را بررسی کنید؛ `/panic` تلاش می‌کند سفارش‌ها و پوزیشن نماد را تعیین تکلیف کند و فقط پس از تأیید خالی بودن آن‌ها وضعیت نامشخص را پاک می‌کند. گزارش سود این نوع معامله ممکن است کامل نباشد.

## ۱۳. خطاهای رایج

| پیام یا نشانه | اقدام |
| --- | --- |
| `Invalid configuration` | نام متغیر اعلام‌شده را در `.env` اصلاح کنید؛ عددها انگلیسی و اعشار با نقطه باشند |
| `Conflict: terminated by other getUpdates` | اجرای دوم یا ابزار دیگری که همان توکن را polling می‌کند متوقف کنید |
| پیام شروع نمی‌رسد | به ربات `/start` بفرستید؛ توکن، chat ID، شبکه و لاگ را بررسی کنید |
| `401` / `403` از API | اعتبار کلید، مجوز، محیط Demo/اصلی و دسترسی منطقه‌ای سرویس را بررسی کنید |
| `429` از Gemini | سهمیه حساب تمام شده یا نرخ درخواست زیاد است؛ بودجه محلی دسترسی بیشتر ایجاد نمی‌کند |
| `Symbol ... not found` | فرمت قراردادی `BTC/USDT:USDT` و بازار انتخابی را بررسی کنید |
| حجم کمتر از حداقل صرافی | طرح با موجودی/فاصله استاپ فعلی قابل اجرا نیست؛ برنامه معامله را رد می‌کند |
| `Another bot ... DATA_DIR` | فرایند قبلی را متوقف کنید؛ حذف فایل قفل فرایند فعال را آزاد نمی‌کند |
| سفارش UNKNOWN یا خروج تأییدنشده | حساب صرافی را بررسی کنید و پیام‌های `/panic` را تا تأیید نهایی دنبال کنید |

برای دیدن آخرین لاگ در ویندوز:

```powershell
Get-Content .\data\bot.log -Tail 100 -Wait
```

قبل از اشتراک لاگ، اطلاعات حساب و کلیدها را بازبینی و حذف کنید. جزئیات بررسی و محدودیت‌های باقی‌مانده در `AUDIT_FA.md` آمده است.
